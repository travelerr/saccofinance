# Sacco Premium billing setup

Implementation verified locally; production Stripe resources and AWS runtime settings are prepared. Live checkout stays disabled until activation and verification. USD pricing: $10 monthly and $100 annually. No trial, no promotion codes, and cancellation at the paid period end. Renewal failures have seven days from the first failure event; repeat retries never extend the window. Failed first payments receive no access.

## Production

1. Create live prices and a live portal configuration in the same Stripe account without modifying Systeme.io products or its webhooks. Configure Stripe renewal retries/emails to match the seven-day grace policy (avoid ending a subscription early during the promised grace window).
2. Create a dedicated Stripe webhook endpoint at `https://saccofinancial.com/api/stripe/webhook` for checkout.session.completed; customer.subscription.created/updated/deleted/paused/resumed; invoice.paid/payment_failed/payment_action_required. Use the current API version. Copy its live signing secret privately.
3. Store a JSON object containing STRIPE_SECRET_KEY, STRIPE_WEBHOOK_SECRET, and SUPABASE_SECRET_KEY in AWS Secrets Manager. Grant the Amplify SSR compute role secretsmanager:GetSecretValue on that specific secret ARN (and kms:Decrypt on its specific key if using a custom KMS key). No client or build role needs these secret values. The website reads secrets server-side via IAM and caches them for five minutes.
4. Add only nonsecret settings to Amplify: STRIPE_MODE=live; STRIPE_BILLING_ENABLED=false for the initial deployment (true only at activation); STRIPE_MONTHLY_PRICE_ID; STRIPE_ANNUAL_PRICE_ID; STRIPE_PORTAL_CONFIGURATION_ID; BILLING_SECRETS_ARN; BILLING_AWS_REGION. The preparation script copies these to the server runtime file. It never copies Stripe or Supabase secret keys to build artifacts.
5. Set AUTH_SITE_URL and Supabase's Site URL to https://saccofinancial.com, allow https://saccofinancial.com/premium/auth/** for welcome links, sign-in links and existing auth callbacks, and configure/verify signup email delivery. Pricing is dynamically rendered, so an environment change cannot leave a cached sales page with different billing availability.
6. Enable anonymous sign-ins with production CAPTCHA/rate-limit configuration and document cleanup of unpaid temporary users. Never delete paid guest source users: retained payment records reference them, even after ownership is claimed. Anonymous sessions still require verified paid access, and have no billing write rights.
7. Deploy and verify member/nonmember account access, signed webhook delivery, checkout price selection, portal cancellation, graceful payment failures, and manual grant protection. Do not activate real checkout until these checks and the public subscription terms are approved.

## Access and reliability

A signed webhook or a server-retrieved, owner-checked completed Stripe Checkout Session with matching configured prices, customer mapping, and Supabase member metadata updates billing access. Success redirect parameters alone never grant access: the return handler retrieves the current Stripe session and reconciles paid invoice evidence through the same idempotent database function. The handler re-reads Stripe's current subscription and verifies paid invoice lines. Event receipt and subscription state update happen in one PostgreSQL transaction; repeats are idempotent and older concurrent reconciliations cannot overwrite newer observations. Test and live records are separate. Authenticated users may read only their own billing rows and cannot call write functions or alter subscriptions directly through Supabase.

The app checks paid-through and grace timestamps on each request, so expiration does not depend on a scheduled job. It fails closed on subscription lookup errors while preserving valid manual grants. Errors return retryable webhook failures without exposing credentials. Account management persists after expiry; open checkout reuse and database reservation avoid duplicate purchases. An abandoned reservation without a created session can block switching plans for 31 minutes; the account page explains that retry condition.

Refunds/dispute policy, annual/monthly plan switching, promotional discounts, trials, and a custom billing admin UI are deferred. Stripe remains the payment-method/invoice manager; card details are never stored by the site.

## Scheduled cancellation

Apply `supabase/migrations/202609170003_scheduled_cancellation.sql` once. Stripe may schedule cancellation using `cancel_at` while `cancel_at_period_end` remains false. Persist both independently. The member page shows nonrenewal and access through the earlier of the verified paid-through date and scheduled cancellation date. Resuming renewal clears the scheduled date. Account & Billing synchronizes only the authenticated member's owned subscriptions from Stripe before rendering; a refresh failure shows the last-verified-state notice. No redirect query parameter grants access or selects an unowned subscription. Lifetime grants are independent and unchanged.
